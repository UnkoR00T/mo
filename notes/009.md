# 009_net.md

### Rola
`h/l1.java` to biblioteczny helper **CameraX `camera-camera2-pipe`** (`Camera2Config`/`CameraCaptureRequestBuilder`), a konkretnie `Camera2Config.Extension` - statyczne metody `a/b/c` do łączenia mapy parametrów oraz ustawiania parametrów na `android.hardware.camera2.CaptureRequest.Builder`. Logowanie błędów przez Sentry (`io.sentry.android.core.c2.h("CXCP", ...)`). Zero logiki aplikacji.

### Endpointy
brak

### Modele danych
- `h.l1` -> `androidx.camera.camera2.interop.Camera2Config.InterfaceBase`/`Extension`-owy helper Camera2 (biblioteka CameraX): `a(Map,Map)` merge map, `b(CaptureRequest.Builder,Object,Object)` set key, `c(CaptureRequest.Builder,Map)` set wszystkich (plik: `h/l1.java`)
- `io.sentry.android.core.c2` -> `SentryLogger` (biblioteka Sentry) (plik: `h/l1.java`)

### Logika
- `b`: ignoruje klucze niebędące `CaptureRequest.Key`; przy `IllegalArgumentException` loguje do Sentry z tagiem `"CXCP"` zamiast rzucać wyjątek (nie przerywa przechwytywania zdjęcia) (plik: `h/l1.java`)
- `c`: iteruje po mapie i wywołuje `b` dla każdego wpisu (plik: `h/l1.java`)

### UI / metryki
brak

### Brakujące klasy
- `io.sentry.android.core.c2` (SentryLogger), `k.k` (Custom logger) - biblioteki, poza zakresem.
