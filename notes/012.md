# 012_net.md

### Rola
`i/AndroidCameraDevice.java` (część 3/9) - biblioteczna klasa **CameraX `androidx.camera.camera2.internal.AndroidCameraDevice`**. Zawiera wyłącznie `O0(ExtensionSessionConfigData)` = `createExtensionSession` (sesja rozszerzenia aparatu, np. Night mode / bokeh na aparatach z rozszerzeniami Camera2). Zero logiki aplikacji mObywatela.

### Endpointy
brak

### Modele danych
- `i.AndroidCameraDevice.O0` -> `AndroidCameraDevice.createExtensionSession` (metoda biblioteki CameraX, nie klasa) (plik: `i/AndroidCameraDevice.java`)
- `l3` -> `CameraXOutputConfig` (interfejs CameraX) - `config.d()` zwraca listę wyjść, mapowanych do `android.hardware.camera2.params.OutputConfiguration` przez `c0(fr.q0.c(OutputConfiguration.class))` (plik: `i/AndroidCameraDevice.java`)
- `o2.a` -> `CameraXExtensionStateCallback` (interfejs CameraX) (plik: `i/AndroidCameraDevice.java`)
- `e0` -> `Camera2ExtensionSessionConfigHelper` (budowa `ExtensionSessionConfiguration`, statyczne `f(...)`; `e0.b(cameraDevice, config)` = wywołanie `CameraDevice.createExtensionSession`; `h0.e(...)` = ustawienie `postviewOutputConfiguration` na API 34+) (plik: `i/AndroidCameraDevice.java`)
- `h0` -> `Camera2PostviewHelper` (dla `Build.VERSION.SDK_INT >= 34`) (plik: `i/AndroidCameraDevice.java`)
- `i.l` -> `CameraXExtensionSessionStateCallback` (wewnętrzna klasa sesji rozszerzenia) (plik: `i/AndroidCameraDevice.java`)

### Logika
- Walidacja wejścia: brak `extensionStateCallback` -> `IllegalStateException("extensionStateCallback must be set to create Extension session")`; brak `extensionMode` -> `IllegalStateException("extensionMode must be set to create Extension session")` (plik: `i/AndroidCameraDevice.java`)
- `j(extensionStateCallback)`: przy zamkniętym urządzeniu zwraca `false` (bez tworzenia sesji); w przeciwnym razie finalizuje poprzednią sesję (`k(b4VarB)`) (plik: `i/AndroidCameraDevice.java`)
- Budowa `ExtensionSessionConfiguration`: `e0.f(extensionMode, lista OutputConfiguration, executor, <ExtensionStateCallback>)`; opcjonalnie, gdy `postviewOutputConfiguration != null` i API >= 34, dokłada wyjście postview (`h0.e(...)`), a brak możliwości rozpakowania konfiguracji -> `IllegalStateException("Failed to unwrap Postview OutputConfiguration")`; następnie `e0.b(cameraDevice, extensionSessionConfiguration)` (plik: `i/AndroidCameraDevice.java`)
- Klasyfikacja wyjątków (identyczna jak w 010/011_net.md): `CameraAccessException` -> `cameraErrorListener.a(cameraId, h.q.INSTANCE.b(e), true)` + log Sentry `"Camera encountered an error"`; `IllegalArgumentException`/`SecurityException`/`UnsupportedOperationException`/`NullPointerException` -> `h.q.INSTANCE.m(), false` + `"Unexpected exception"`; `IllegalStateException` -> sam log; inne -> rethrow (plik: `i/AndroidCameraDevice.java`)
- Niepowodzenie -> log Sentry `"Failed to create extension session from " + cameraDevice + ". Finalizing previous session"` + `l(b4Var)` (finalizacja sesji) (plik: `i/AndroidCameraDevice.java`)
- Pomiar czasu: `Trace.beginSection("CXCP#createExtensionSession-" + getCameraId())` / `endSection()`, czas monotoniczny w ns konwertowany przez `k.i.c(...)` i dzielony przez `1_000_000.0` do `"%.3f ms"` (plik: `i/AndroidCameraDevice.java`)

### UI / metryki
brak. Metryka wewnętrzna: czas trwania `createExtensionSession` w ms z 3 miejscami po przecinku (log, nie UI); błędy idą do Sentry z tagiem `"CXCP"`.
