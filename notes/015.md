### Logika
- `t0(config)`: najpierw `j(config.getStateCallback())` zwraca pare `(czy-zamknieto, ostatni callback stanu)`; jesli `false` -> natychmiastowy `return false` (plik: `i/AndroidCameraDevice.java`)
- Poprzednia sesja jest finalizowana przez `k(b4VarB)` jesli callback istnieje (plik: `i/AndroidCameraDevice.java`)
- Zbieranie wyjsci: lista `config.c()` mapowana przez `c0(fr.q0.c(OutputConfiguration.class))` na `OutputConfiguration` - elementy innego typu powoduja blad (brak rzutowania/konwersji) (plik: `i/AndroidCameraDevice.java`)
- Bufor wejsciowy: `Build.VERSION.SDK_INT >= 31` -> `e0.g(config.b(), getCameraId())`, wczesniej jawne `InputConfiguration(width, height, format)` (plik: `i/AndroidCameraDevice.java`)
- Przestrzen kolorow: tylko od API 34 (`sessionColorSpace != null`); nierozpoznana nazwa loguje `"Provided session color space <x> is not supported"`, a na API < 34 komunikat `"Failed to set session color space to <x>, at least API level 34 is required"` - brak wyjatku, operacja cicho pomijana (plik: `i/AndroidCameraDevice.java`)
- Filtr kluczy: z `cameraMetadata.H0()` budowana jest lista nazw kluczy; z `config.e()` przepisywane sa wylacznie te pary, ktorych klucz jest `CaptureRequest.Key` **i** jego nazwa występuje na liscie; pozostale pomija sie (plik: `i/AndroidCameraDevice.java`)
- Budowa i zapis sesji w sekcjach Trace: `"CXCP#createCaptureSession-<cameraId>"`, `"createCaptureRequest"`, `"Api28Compat.createCaptureSession"` (plik: `i/AndroidCameraDevice.java`)
- `w.l(...)` przypisuje zbudowany `CaptureRequest` do `SessionConfiguration`, `w.a(...)` wywoluje natywne `createCaptureSession` (plik: `i/AndroidCameraDevice.java`)
- W przypadku niepowodzenia (bladlog `"Failed to create capture session from <CameraDevice>. Finalizing previous session"`) finalizowana jest poprzednia sesja przez `l(b4VarB)`, a metoda zwraca `false` (plik: `i/AndroidCameraDevice.java`)
- Pomiar czasu: nanosekundy z `k.h.g().a()`, dzielone przez `1000000.0d`, formatowane jako `"%.3f ms"` tylko gdy `k.k.a()` (plik: `i/AndroidCameraDevice.java`)
- Bloki obslugi bledow powielone przez dekodowanie JADX (`catch (Throwable)` z 10 poziomow) - powtarzaja ten sam schemat co 014; czesc `if`/`else` zdekodowana blednie (np. `if (!(e instanceof CameraAccessException))` zamiast odwrotnie) - kod nieczytelny w tych miejscach (plik: `i/AndroidCameraDevice.java`)
