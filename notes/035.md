# 035_net.md

### Rola
`kc/h.java` to biblioteczna klasa **Glide** (`kc.h` = singleton `Glide` z `com.bumptech.glide`), trzymająca globalny rejestr komponentów ładowania obrazów: interceptorów, mapperów modeli, keyerów oraz leniwych list fabryk fetcherów i dekoderów. Nie jest to kod aplikacji mObywatel - brak logiki domenowej.

### Endpointy
brak - klasa nie wykonuje żadnych wywołań sieciowych (pobieranie obrazów jest w `qc.SourceFetchResult` i interceptorach `rc.d`, poza tą paczką).

### Modele danych
- `h` -> "Glide (rejestr komponentow)": `interceptors: List<rc.d>`, `mappers: List<pair<tc.c, mr.c>>`, `keyers: List<pair<sc.c, mr.c>>`, `lazyFetcherFactories`, `lazyDecoderFactories`, `fetcherFactories: oq.k` (lazy), `decoderFactories: oq.k` (lazy) - `kc/h.java:23-44`.
- `h.a` -> "Builder rejestru" z metodami `i(interceptor)`, `j(keyer, type)`, `k(mapper, type)`, `h(fetcherFactory, type)`, `g(decoderFactory)`, `n(...)`, `o(...)`, `p()` -> `new h(...)` - `kc/h.java:47-169`.
- `qc.SourceFetchResult` -> "WynikPobraniaZrodla" (wejscie `j(Object data, Options options)`), `zc.Options` -> "OpcjeZadania" (rozmiar/skalowanie/obraz docelowy), `s` -> "ImageLoader" - `kc/h.java:220-257`.
- `oc.i.a` -> fabryka dekoderów (`DecoderFactory`), `qc.j.a` -> fabryka fetcherów (`DataFetcher.Factory`), `mr.c` -> `Class<T>` (typ docelowy), `tc.c`/`sc.c` -> mapper i keyer - `kc/h.java:29-35, 53-62`.

### Logika
- Leniwa inicjalizacja: `fetcherFactories` / `decoderFactories` (`oq.l.a(er.a)`) wywołują statyczne `d(h)` / `c(h)`, które rozwijają listę leniwych fabryk do płaskiej listy, wywołując `getValue()` na każdej, a następnie **wyczyszczają** listę leniwą (`pq.v.n()`) - czyli każda fabryka jest materializowana najwyżej raz - `kc/h.java:176-198, 271-282`.
- `j(data, options)`: iteruje po `mappers` w kolejności rejestracji; dla każdego, gdy `type.A(data)` (dopasowanie typu) i mapper zwróci nie-null, wynik **zastępuje** bieżące `data`; łańcuch mapowań - `kc/h.java:220-232`.
- `l(result, options, imageLoader, startIndex)` i `m(data, options, imageLoader, startIndex)`: iterują dekodery/fetchery od `startIndex` i zwracają pierwszy pasujący wraz z jego indeksem (`oq.y.a(znaleziony, Integer)`), czyli wynik wskazuje **który** dekoder obsłużył dane; `null` gdy żaden - `kc/h.java:238-262`.
- Builder `p()` tworzy nowy `Glide` z kopiami list (`ed.c.c(...)`) - `kc/h.java:159-161`.
- Konstruktor bezargumentowy `h()` = rejestr pusty - `kc/h.java:285-287`.
- Brak własnych interwałów, retry/backoff.

### UI / metryki
brak - brak odwołań do widoków aplikacji. `Options`/`ImageLoader` są typami biblioteki, nie parametrami ekranów mObywatela.

### Brakujące klasy
- `kc.h.d`, `kc.h.e`, `kc.h.f`, `kc.h.g` (klasy anonimowe z `// from class:`) - wewnętrzne implementacje `er.a` dla leniwych list.
- `rc.d` (interceptor Glide), `qc.j`/`qc.j.a` (DataFetcher), `oc.i`/`oc.i.a` (Decoder), `mr.c`, `tc.c`, `sc.c`, `ed.c` - pozostałe klasy Glide (pakiety `rc`, `qc`, `oc`, `mr`, `tc`, `sc`, `ed`), poza zakresem.
- `oq.k`/`oq.l`/`oq.r`/`oq.y` - leniwa DI aplikacji (Koin) użyta jako kontener lazy, poza zakresem.
