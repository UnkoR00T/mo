# 055_net.md

### Rola
`nv/f.java` (część 5/5) to końcówka **`okhttp3.internal.http2.Http2Connection`** — publiczne API połączenia HTTP/2: handshake (connection preface, SETTINGS), wysyłanie nagłówków i danych DATA z kontrolą przepływu (okno połączenia), obsługa PUSH_PROMISE (`s1`/`x1`), keepalive oraz `close()`. Zero logiki aplikacji.

### Endpointy
brak (brak URL-i, nagłówków warstwy aplikacji i Retrofit — surowy protokół HTTP/2 na `Socket`)

### Modele danych
- `nv.f` -> `Http2Connection`; pola dopiero w tej części: `readBytesTotal: long`, `readBytesAcknowledged: long` (realizacja odbioru i potwierdzenia okna), `okHttpSettings/peerSettings: m`, `nextStreamId`, `lastGoodStreamId`, `isShutdown`, `degradedPingsSent/PongsReceived`, `degradedPongDeadlineNs` (plik: `nv/f.java`)
- `nv.j` -> `FrameWriter`: `h()` = connection preface, `J(Settings)` = SETTINGS, `K(streamId, delta)` = WINDOW_UPDATE, `y/E/m` = HEADERS/PING/DATA, `getMaxFrameSize()`, `flush()` (plik: `nv/f.java`)
- `nv.c` -> `Headers` (klatkowe), `nv.b` -> `ErrorCode` (`NO_ERROR`, `CANCEL`), `nv.i` -> `Http2Stream` (plik: `nv/f.java`)
- `vv.e` -> `Buffer` (bufor bajtów), `vv.g` -> `Source` (źródło danych) — biblioteka okio

### Logika
- `d2(sendConnectionPreface, taskRunner)`: jeśli preface, wysyła `h()`, potem `J(okHttpSettings)`, a jeśli `okHttpSettings.c() != 65535`, wysyła WINDOW_UPDATE o delta `c() - 65535` dla strumienia 0 (powiększenie początkowego okna); uruchamia `readerRunnable` w kolejce z opóźnieniem 0 (plik: `nv/f.java`)
- `j2(read)` (przepływ odczytu): sumuje `readBytesTotal`; gdy niepotwierdzony limit (`readBytesTotal - readBytesAcknowledged`) osiągnie połowę okna (`okHttpSettings.c() / 2`), wysyła WINDOW_UPDATE i zwiększa `readBytesAcknowledged` (kredyt przepływu = 50% okna) (plik: `nv/f.java`)
- `t2(streamId, outFinished, buffer, byteCount)` (przepływ zapisu): pętla dzieląca dane na porcje `min(byteCount, writeBytesMaximum - writeBytesTotal, writer.getMaxFrameSize())`; jeśli okno połączenia wyczerpane, `wait()` na monitorze (blokada powiadamiana przez `K1`/`notifyAll`), przerwanie → `InterruptedIOException`, zamknięty strumień → `IOException("stream closed")` (plik: `nv/f.java`)
- `d1(nowNs)` (keepalive degraded): `false` gdy `isShutdown`; w przeciwnym razie `degradedPongsReceived >= degradedPingsSent || nowNs < degradedPongDeadlineNs` (plik: `nv/f.java`)
- `s1`/`x1`: zdarzenia PUSH (DATA / HEADERS) kolejkowane w `pushQueue` z opóźnieniem 0; `s1` dodatkowo raportuje `byteCount` do źródła (limit bajtów okna strumienia) (plik: `nv/f.java`)
- `y2(reply, p1, p2)` → `writer.E` (PING/PONG); `IOException` → `a0(...)` ( zamknięcie z `PROTOCOL_ERROR`) (plik: `nv/f.java`)
- `close()` → `Z(NO_ERROR, CANCEL, null)` (GOAWAY NO_ERROR, reset strumieni CANCEL, zamknięcie socketu) (plik: `nv/f.java`)
- Retry/backoff: brak; interwały: keepalive PING/degraded deadline 1 s (z `054_net.md`), oczekiwanie na okno = `wait()` bez limitu czasu
