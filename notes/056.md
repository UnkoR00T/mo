# 056_net.md

### Rola
`nv/i.java` (część 1/2) to wnętrzne API **okhttp3.internal.http2.Http2Stream** — jednego strumienia HTTP/2: implementacja `vv.j0` (`Sink`) do zapisu body oraz `vv.k0` (`Source`) do odczytu body, z kontrolą przepływu okna strumienia i obsługą trailerów. Zero logiki aplikacji.

### Endpointy
brak (brak URL-i, nagłówków warstwy aplikacji i Retrofit — surowy protokół HTTP/2 na strumieniu)

### Modele danych
- `nv.i` -> `Http2Stream`: pola `id: int`, `connection: Http2Connection` (nv.f), `sink: b`, `source: c`, `readTimeout/writeTimeout: vv.l0` (Timeout), `errorException: IOException`, `readBytesTotal/readBytesAcknowledged: long`, `writeBytesTotal/writeBytesMaximum: long`, `canceled: boolean`; metody `h()` (pobranie błędu), `D()` (poczekaj na zmianę stanu monitor), `notifyAll` (plik: `nv/i.java`)
- `nv.i$b` -> `Http2Stream$SinkImpl`: `sendBuffer: vv.e`, `finished: boolean`, `closed: boolean`, `trailers: u` (Headers) (plik: `nv/i.java`)
- `nv.i$c` -> `Http2Stream$SourceImpl`: `maxByteCount: long` (limit okna strumienia), `receiveBuffer/readBuffer: vv.e`, `finished/closed: boolean`, `trailers: u` (plik: `nv/i.java`)
- `nv.i$d` -> `Http2Stream$StreamTimeout`: deleguje `l0` (Timeout) i mapuje `SocketTimeoutException`/`InterruptedIOException`; zawiera referencję `"okhttp"` (plik: `nv/i.java`, string `"okhttp"` w metadanych)
- `nv.n` -> `StreamResetException` (IOException opakowująca kod resetu), `nv.u` -> `Headers`, `nv.b` -> `ErrorCode`, `vv.e`/`vv.g`/`vv.j0`/`vv.k0`/`vv.l0`/`vv.k0` -> `okio` `Buffer`/`Source`/`Sink`/`Timeout` (plik: `nv/i.java`)

### Logika
- `b.b(outFinishedOnLastFrame)` (zapis): pod `synchronized(i)` pętla `while (writeBytesTotal >= writeBytesMaximum && !finished && !closed && error == null) D()` — blokada na oknie połączenia z `writeTimeout` (enter/exit `s()`/`C()`); oblicza `jMin = min(writeBytesMaximum - writeBytesTotal, sendBuffer.size)`, zwiększa `writeBytesTotal`, ustala flagę zakończenia, deleguje do `connection.t2(id, outFinished, sendBuffer, jMin)` (plik: `nv/i.java`)
- `O3(source, byteCount)` (`Sink.write`): dołącza do `sendBuffer` i płucze (`b(false)`) dopóki `sendBuffer.size >= 16384` (16 KiB) — minimalny porcjowany blok zapisu; asercja że wątek nie trzyma monitora strumienia (plik: `nv/i.java`)
- `b.close()`: jeśli sink nie `finished` — wariant z trailerami (`connection.v2(id, outFinished, Headers.O(trailers))`), wariant z danymi (`b(true)` w pętli) lub pusty zapis z `t2(id, true, null, 0L)`; następnie `closed = true`, `connection.flush()` (plik: `nv/i.java`)
- `b.flush()`: pętla `while sendBuffer.size > 0` { `b(false)`; `connection.flush()` } (plik: `nv/i.java`)
- `c.k3(sink, byteCount)` (odczyt): pod monitorem odrzuca `byteCount < 0`; ustala `errorException` (z `h()` lub nowy `StreamResetException`); rzuca `IOException("stream closed")` gdy `closed`; jeśli `readBuffer.size > 0` kopiuje `min(byteCount, size)` i raportuje okno: gdy `readBytesTotal - readBytesAcknowledged >= okHttpSettings.c() / 2` → `connection.N2(id, readBytesTotal)` + `z(readBytesTotal)`; inaczej `D()` i pętla (blokada do danych); zwraca `-1L` na koniec, `-1`/`0` jako sygnał (plik: `nv/i.java`)
- `c.m(source, byteCount)` (odbiór DATA): jeśli `readBuffer.size + remaining > maxByteCount` → `source.skip(...)` + `f(nv.b.FLOW_CONTROL_ERROR)` (przekroczenie okna = błąd); jeśli `finished` → `skip`; kopiuje do `receiveBuffer`, scala z `readBuffer`, `notifyAll()` przy pierwszych danych; po pętli raportuje `u(byteCount)` → `connection.j2(read)` (plik: `nv/i.java`)
- `c.close()`: `closed = true`, odrzuca `readBuffer`, `notifyAll()`, raportuje niewykorzystany limit okna, zamyka strumień (plik: `nv/i.java`)
- Retry/backoff: brak. Interwały: brak (timeouty z `writeTimeout`/`readTimeout`); progi: 16384 B na porcję zapisu, 50% okna na WINDOW_UPDATE (z `055_net.md`)
