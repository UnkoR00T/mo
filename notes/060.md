# 060_net.md

### Rola
`ol/c.java` (część 2/2) to druga metoda publiczna klienta **Firebase Installations Service** — generowanie tokenu autoryzacyjnego FIS dla istniejącej instalacji. Nadal biblioteka `com.google.firebase:firebase-installations`, bez logiki aplikacji mObywatel.

### Endpointy
- **POST** `https://firebaseinstallations.googleapis.com/v1/projects/{str3}/installations/{str2}/authTokens:generate` (metoda `e(str, str2, str3, str4)`; URL budowany w `g(String.format("projects/%s/installations/%s/authTokens:generate", projectId, fid))`) — plik: `ol/c.java`
  - parametry: `str` = API key Firebase, `str2` = fid instalacji, `str3` = project ID, `str4` = refresh token instalacji (plik: `ol/c.java`)
  - nagłówki: `Authorization: FIS_v2 <refreshToken>` (nagłówek dodawany w `e`, plik: `ol/c.java`) oraz wspólne z `l()`: `Content-Type: application/json`, `Accept: application/json`, `Content-Encoding: gzip`, `Cache-Control: no-cache`, `X-Android-Package`, `x-firebase-client`, `X-Android-Cert`, `x-goog-api-key`
  - body: gzip `{"installation":{"sdkVersion":"a:19.1.0"}}` (metoda `r` -> `s`) (plik: `ol/c.java`)
  - odpowiedź 2xx: `{"token": ..., "expiresIn": "<N>s"}` (metoda `p`) (plik: `ol/c.java`)
  - timeouts: connect 10000 ms, read 10000 ms; `TrafficStats.setThreadStatsTag(32771)` (plik: `ol/c.java`)
- Podpisywanie: brak; autoryzacja wyłącznie nagłówkiem `Authorization: FIS_v2 <refreshToken>`

### Modele danych
- `ol.f` -> `AuthToken` (wygenerowany token FIS: `token`, `expiresIn: long`, status `f.b`: `OK`, `AUTH_ERROR`, `BAD_CONFIG`) (plik: `ol/c.java`)
- `ol.e` -> `FirebaseInstallationsStatsLogger` (logowanie kodów odpowiedzi, `b()` = dostępność usługi) (plik: `ol/c.java`)
- `com.google.firebase.installations.d` -> `FirebaseInstallationsException` (enum `d.a`: `UNAVAILABLE`, `TOO_MANY_REQUESTS`) (plik: `ol/c.java`)

### Logika
- `e(...)`: brak dostępności (`!e.b()`) → wyjątek `UNAVAILABLE`; **pętla `for (i15 = 0; i15 <= 1; i15++)`** = 2 próby bez backoffu; po każdej `e.f(responseCode)`; 2xx → `p(connection)` parsujące `token` i `expiresIn` (przez `m()` obcinające `s`); `401` lub `404` → status `AUTH_ERROR` (odnowienie tokena); `429` → wyjątek `TOO_MANY_REQUESTS`; inne kody poza `[500,600)` → `BAD_CONFIG` + ostrzeżenie o konfiguracji Firebase; po dwóch próbach → wyjątek `UNAVAILABLE`; zawsze `disconnect()` + `TrafficStats.clearThreadStatsTag()` (plik: `ol/c.java`)
- Różnica vs część 1/2 (`ol/c.java`, `059_net.md`): znacznik ruchu `32771` (zamiast `32769`) dla żądań tokenu; obsługa `401`/`404` jako `AUTH_ERROR` (zamiast `429`/`BAD_CONFIG`); wyjątki `IOException`/`AssertionError` z jednej próby są połykane i przechodzone do następnej iteracji
- Interwały: 10 s connect, 10 s read; retry: 2 twarde próby
