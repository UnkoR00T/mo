# 069_net.md

### Rola
`pl/gov/coi/common/network/t0.java` to **fabryka serwisów Retrofit** (`ge4.y` = `retrofit2.Retrofit`, `ge4.y.b` = builder) implementująca interfejs `pl.gov.coi.common.network.w`. Dla podanego profilu (`y`) buduje instancję interfejsu API: dobiera base URL (od dostawcy `ay.a`), klienta OkHttp (z profilu `t.Backend` / `t.Public`, z opcjonalnym nadpisaniem timeoutów) i konwerter serializacji JSON (Gson lub kotlinx/codegen). To centralny punkt, w którym aplikacja wiąże adres bazowy + transport + serializację z interfejsem usługi.

### Endpointy
brak literalnych URL-i i ścieżek - adres bazowy jest dynamiczny: `baseUrlProvider.getBaseUrl()` (`ay.a`). Ścieżki, metody HTTP i parametry są zdefiniowane w interfejsach przekazywanych jako `Class<T> service` do `b(service)` (`t0.java:84, 92, 102`). W tej klasie:
- Klient **backend** (domyślny): `httpClientFactory.a(new t.Backend(...))` -> OkHttp z timeoutami, interceptorami, CertificatePinnerem i TLS 1.3 (`t0.java:64`).
- Klient **publiczny**: `httpClientFactory.a(new t.Public(interceptorsProfile))` dla profilu `y.c`, z base URL branym z profilu (`cVar.b()`), **bez** timeout override - `t0.java:84`.
- Klient z **nadpisanym timeoutem**: `httpClientFactory.c(backendClient, timeout)` klonuje klienta i ustawia 4 timeouty z `HttpServiceParameters.getTimeout()` (`t0.java:97`, implementacja `c()` w `md/067_net.md:152-165`).

### Logika
- Dwa leniwe pola (`oq.k`) tworzone w inicjalizatorze: `backendHttpClient` (OkHttp dla profilu `Backend`, `t0.java:30-35`) i `retrofit` (Retrofit z base URL z providera i klientem backend, `t0.java:38-43, 76-78`). Leniwość = klient i Retrofit powstają dopiero przy pierwszym użyciu.
- `e(builder, serializer)` - konfiguracja serializacji:
  - `serializer instanceof o` (Gson) -> `builder.a(he4.a.f(gson))` (Konwerter Gson) - `t0.java:52-54`.
  - `serializer instanceof d0` -> `d0.c()` i dodanie konwertera `rn.c.a(null, fv.x.INSTANCE.a("application/json"))` (konwerter generowany + Content-Type `application/json`) - `t0.java:58-59`.
  - Inny typ -> `throw new ClassCastException("RetrofitHttpServiceFactory needs GsonSerializer")` - `t0.java:56-57`.
- `a(profile, service)` - rozgałęzienie:
  1. `profile instanceof y.c` -> nowy Retrofit z base URL z profilu (`cVar.b()`), klientem `t.Public`, `create(service)` - `t0.java:82-85`.
  2. `profile instanceof y.Backend` i `clientProfile == y.b.a.f158228a` (singleton domyślny) -> **reusing leniwego `retrofit`** i `create(service)` - `t0.java:90-93`.
  3. `profile instanceof y.Backend` i `clientProfile instanceof y.b.C3925b` -> nowy Retrofit z base URL providera, **klon klienta backend z nadpisanym timeoutem** z parametrów serwisu, serializator z parametrów serwisu lub domyślny (gdy `null`), `create(service)` - `t0.java:94-102`.
  4. Inny typ profilu / podprofilu -> `throw new oq.p()` - `t0.java:87, 95`.
- Porównanie podprofilu przez `fr.t.c(clientProfile, y.b.a.f158228a)` - porównanie strukturalne obiektu, nie tożsamości - `t0.java:91`.
- Nie ma własnych interceptorów ani podpisywania w tej klasie - warstwa nagłówków/auth dochodzi z `interceptorsFactory` (`p00.g`) na podstawie profilu interceptorów; konfiguracja interceptorów (w tym `interceptorAuth`, `interceptorDefaultHeaders`, `remoteHttpLoggingInterceptor`, `interceptorDynamicBaseUrlMock`, `blockHttpCleartextInterceptor`) jest opisana w module DI `md/058_net.md`.
