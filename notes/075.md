# 075_net.md

### Rola
Konwerter specyfikacji pracy WorkManagera na natywny `JobInfo` dla `SystemJobService` (Android JobScheduler). Kod biblioteczny androidx.work, bez logiki aplikacji.

### Endpointy
brak — brak komunikacji sieciowej; mapuje wymagania sieciowe (`NetworkType`) na wartości `JobInfo.setRequiredNetworkType` / `NetworkRequest`.

### Modele danych
brak własnych DTO. Używane struktury: `ub.d` -> `WorkSpec.Constraints` (wymagania: ładowanie, idle, sieć, bateria, storage, triggery content URI), `ub.x` -> `NetworkType` enum (NOT_REQUIRED, CONNECTED, UNMETERED, NOT_ROAMING, METERED, TEMPORARILY_UNMETERED), `ub.a` -> `BackoffPolicy` (LINEAR vs exponential), `cc.i0` -> `WorkSpec` (id, generation, runAttemptCount, backoffDelayDuration, expedited, getTraceTag()).

### Logika
- Mapowanie NetworkType na inty API: NOT_REQUIRED->0, CONNECTED->1, UNMETERED->2, NOT_ROAMING->3, METERED->4; dla nieznanej wartości loguje "API version too low" i zwraca 1 (CONNECTED). `xb/d.java:82-101`
- API >= 30 i `TEMPORARILY_UNMETERED` -> `NetworkRequest` z capability 25 zamiast `setRequiredNetworkType`. `xb/d.java:103-109`
- API >= 28 i specyfikacja zawiera `NetworkRequest` -> używa `e.a(builder, networkRequest)`. `xb/d.java:119-125`
- Backoff: `setBackoffCriteria(backoffDelayDuration, LINEAR ? 0 : 1)` ustawiane tylko gdy nie `requiresDeviceIdle`. `xb/d.java:126-128`
- Latencja: `Math.max(c() - clock.a(), 0)`; jeśli API <= 28 lub > 0 -> `setMinimumLatency`, inaczej przy nieekspedytowanym zadaniu i fladze `f217864c` -> `setImportantWhileForeground(true)`. `xb/d.java:129-134`
- Expedite tylko przy API >= 31, `expedited`, `runAttemptCount == 0` i braku wymuszonej latencji. `xb/d.java:147-151`
- Triggery: dla każdego `TriggerContentUri` dodaje `addTriggerContentUri` + opóźnienie aktualizacji i maksymalne opóźnienie. `xb/d.java:135-142`
- Extras (PersistableBundle): `EXTRA_WORK_SPEC_ID`, `EXTRA_WORK_SPEC_GENERATION`, `EXTRA_IS_PERIODIC`. `xb/d.java:114-118`
- `setPersisted(false)` zawsze. `xb/d.java:143`
