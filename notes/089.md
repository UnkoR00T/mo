# 089_model.md

### Rola
Część 4/4 (ostatnia) klasy `androidx.activity.ComponentActivity` (`CON/p.java`) - `CreationExtras` dla ViewModeli, warianty `setContentView`, obsługa `onMultiWindowModeChanged`/`onPictureInPictureModeChanged` z `Configuration` oraz konstruktor z `contentLayoutId`.

### Endpointy
brak.

### Modele danych
- `CreationExtras` (`p7.d` -> `CreationExtras.Builder`) - mapa `DefaultKey`s przekazywana do fabryki ViewModeli: `androidx.lifecycle.w0.a.f12845h` -> Application, `androidx.p016lifecycle.l0.f12795a` -> LifecycleOwner, `...f12796b` -> ViewModelStoreOwner, `...f12797c` -> `Bundle` extras z intencji (dodawane tylko gdy `getIntent().getExtras() != null`) (CON/p.java:45-59).
- `androidx.lifecycle.w0.c` -> `DefaultViewModelCreationExtras` / fabryka ViewModeli (getter `w()`, wartość `defaultViewModelProviderFactory`) (CON/p.java:40-42).
- `s5.i` -> `MultiWindowModeChangedInfo` - wariant z polem `Configuration`: `isInMultiWindowMode: boolean`, `newConfig: Configuration` (CON/p.java:78-92).
- `s5.t` -> `PictureInPictureModeChangedInfo` - wariant z polem `Configuration`: `isInPictureInPictureMode: boolean`, `newConfig: Configuration` (CON/p.java:94-108).
- `CON.p.contentLayoutId: int` - ustawiany w konstruktorze `p(int)`, używany w `onCreate` do `setContentView` (CON/p.java:124-127, 141-144 w 088).

### Logika
- `x()`: buduje `CreationExtras` warunkowo - Application tylko gdy `getApplication() != null`; LifecycleOwner i ViewModelStoreOwner zawsze; extras intencji tylko gdy niepuste (CON/p.java:45-59).
- `onMultiWindowModeChanged(boolean, Configuration)` i `onPictureInPictureModeChanged(boolean, Configuration)`: flaga `dispatchingOn*Changed = true` na czas `super`, potem `false` i rozproszenie do nasłuchów; w `catch (Throwable)` flaga również zerowana i wyjątek ponownie rzucony (try/finally ręczny) (CON/p.java:78-108).
- Wszystkie trzy przeciążenia `setContentView(View)`, `setContentView(View, LayoutParams)` i `setContentView(int)` wywołują `h0()` + `reportFullyDrawnExecutor.c0(decorView)` przed `super` (CON/p.java:110-122).
- `y(j6.r)` usuwa providera z `menuHostHelper.f(...)` (CON/p.java:61-64).
- `startActivityForResult`/`startIntentSenderForResult` (z Bundle i bez) - czyste przesłania do `super` (puste nadpisania wygenerowane przez jadx) (CON/p.java:66-76).
- Konstruktor `p(int contentLayoutId)` deleguje do `p()` i ustawia `contentLayoutId` (CON/p.java:124-127).

### UI / metryki
brak domenowych ekranów/wykresów. Metryka: `reportFullyDrawnExecutor`/`FullyDrawnReporter` (czas do pełnego wyrenderowania aktywności), analogicznie jak w 086-088.
