# 094_model.md

### Rola
Klasa `c3.SnapshotStateList<T>` z `androidx.compose.runtime.snapshots` - lista obserwowana przez Compose Snapshot (część 1 z 2). Realizuje `List<T>`/`Parcelable` nad niezmienną strukturą `t2.e` (PersistentList) zapisującą zmiany w systemie snapshotów.

### Endpointy
brak.

### Modele danych
- `c3.SnapshotStateList<T>` -> `SnapshotStateList<T>` (implementuje `java.util.List<T>`, `Parcelable`, interfejs stanu `c3.u0`):
  - `firstStateRecord: c3.w0` -> `StateObject` (bieżący rekord stanu; `getFirstStateRecord()`/`l(w0)`; wewnętrznie castowany do `c3.p0` = `ListStateRecord<T>`) (094:199-207).
  - CREATOR (klasa wewnętrzna, nazwa zaciemniona) - `createFromParcel(Parcel[, ClassLoader])`: czyta `int` (rozmiar) i odbudowuje listę przez `SnapshotStateList.a.d(parcel, loader, rozmiar)`; `newArray(size)` tworzy `SnapshotStateList[size]`; domyślny `ClassLoader` = `a.class.getClassLoader()` (094:37-62).
- `c3.p0` -> `ListStateRecord<T>` (rekord stanu listy): `getModification(): int` (licznik modyfikacji), `getStructuralChange(): int` (licznik zmian strukturalnych), `j(): t2.e<T>` (bieżąca lista), `m(...)`/`n(int)`/`o(int)` - odpowiednio przypisanie listy, zwiększenie modyfikacji i strukturalnej zmiany (094:86-98, 117-127, 162-166).
- `c3.o0` -> `SnapshotStateListIterator` (implementacja `ListIterator<T>`, tworzona w `listIterator()`) (094:215-217).
- `t2.e` -> `kotlinx.collections.immutable.PersistentList<T>`, `t2.e.a` -> `PersistentList.Builder<T>` (z `builder()`, `subList().clear()/retainAll()`, `build()`, `T0(index)` - update, `add`, `removeAll`) (094:91-99, 168, 231-233, 259-261, 293).
- `c3.w0` -> `StateObject`, `c3.u0` -> `StateObject`-interfejs, `c3.g0` -> `SnapshotStateListKt` (helpery: `a`, `f`, `g`, `k`, `l`, `f22814a` = blokada globalna), `c3.l` -> `Snapshot` (singleton `INSTANCE`, `c()` = `takeMutableSnapshot`-ish), `w` -> `SnapshotStateKt`/`StateKt` (`I`, `M`, `n0`, `V` - operacje na rekordach i blokadach) (094:64-72, 85-100).

### Logika
- `add(T)`: pętla do skutku - pod blokadą `g0.f22814a` odczyt `getFirstStateRecord()`, `getModification()` i `j()`; `PersistentList.add(element)`; jeśli `equals` starej listy (brak zmiany) -> `false`; `clear` zapisuje nową listę, `getModification()+1`, `getStructuralChange()+1` pod blokadą, całość w `Snapshot` (`l.INSTANCE.c()` / `w.V(...)`); powtórka przy konflikcie (094:78-103).
- `addAll(index, elements)` / `retainAll(elements)` / `clear()` analogicznie przez `g0.k(...)` i `w.n0(...)` (094:105-113, 116-129, 308-315).
- `i(int index)` (setter `remove(int)` bridge): update `PersistentList.T0(index)`; przy braku zmiany zwraca starą wartość; w pętli do skutku (094:155-180, 275-278).
- `n(fromIndex, toIndex)`: `builder().subList(fromIndex,toIndex).clear()` (094:219-244).
- `q(Collection, start, end)`: `subList(start,end).retainAll(elements)` i zwraca `rozmiarPrzed - rozmiarPo` (liczba usuniętych elementów) (094:246-273).
- Odczyty (`get`, `h()` = `size`, `contains`, `containsAll`, `indexOf`, `lastIndexOf`, `isEmpty`, `iterator`, `listIterator`) nie tworzą snapshotu - idą wprost do `g0.g(this).j()` (094:131-139, 146-153, 182-190, 192-195, 209-217).
- `removeAll(elements)` -> `PersistentList.removeAll(...)`, `false` gdy brak zmiany (094:280-305).
- `describeContents()` = 0 (brak plików) (094:141-145).
- `g(...)`/`o(...)`: `list.addAll(index, collection)` i `list.retainAll(collection)` - pomocnicze lambdy do `g0.k` (094:69-76).

### UI / metryki
brak własnych ekranów. `SnapshotStateList` jest kontenerem stanu dla Compose UI (np. listy elementów widoku); liczniki `getModification()`/`getStructuralChange()` to wewnętrzne metryki inkrementalności stanu, nie metryki biznesowe.
