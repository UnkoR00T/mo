# 106_model.md

### Rola
Wrapper (koperta) odpowiedzi API dla danych karty emeryta: łączy `PensionerCardData` (kontener danych) z `xh2.a` (nagłówek danych / metadane odpowiedzi). Klasa `Parcelable` + `Serializable`, używana jako element listy kart.

### Endpointy
brak (to DTO; sam pakiet nie zawiera interfejsu sieciowego)

### Modele danych
`ci2.PensionerData` (obf `ci2.c`, plik `ci2/PensionerData.java`):

| obf | adnotacja | typ | czytelna nazwa | znaczenie |
|---|---|---|---|---|
| a | `@vl.c("dc")` | `PensionerCardData` (`ci2.a`) | `dataContainer` | dane karty emeryta/rentisty (zob. 105_model.md) |
| b | `@vl.c("dh")` | `xh2.a` | `dataHeader` | wspólny nagłówek/envelope odpowiedzi backendu (wersjonowanie, status, daty) |

- `ci2.PensionerData$a` -> **CREATOR** (`Parcelable.Creator`): `createFromParcel` = `PensionerCardData.CREATOR.createFromParcel(parcel)` + `parcel.readSerializable()` (xh2.a) - kolejność: kontener pierwszy, nagłówek drugi (`ci2/PensionerData.java:39`).
- `writeToParcel`: `dataContainer.writeToParcel(...)` potem `dest.writeSerializable(dataHeader)` (`:90`) - odwrotność poprawnej.
- `describeContents()` = 0 (brak plików).
- `equals` przez `t.c` na obu polach (`:77`); `hashCode` = `dataContainer.hashCode()*31 + dataHeader.hashCode()` - **bez null-checków** (`:81`), potencjalny NPE gdy `dataContainer`/`dataHeader` są null.
- `toString`: `PensionerData(dataContainer=..., dataHeader=...)` (`:85`).

### Logika
Bez logiki biznesowej, przeliczeń i agregacji. Jedyna obserwacja: `hashCode`/`toString` nie maskują PESEL-a (PensionerCardData.toString zwraca pełne dane), więc te wartości nie powinny trafiać do logów produkcyjnych.

### UI / metryki
Brak UI w tym pliku. Klasa jest typem pozycji w kolekcji kart (Parcelable -> przekazywana w Intent/Bundle). Nagłówek `dataHeader` prawdopodobnie niesie status/metadata odpowiedzi pokazywane przy wyświetlaniu listy dokumentów.

### Brakujące klasy
- `xh2.a` - wspólny `dataHeader` (envelope) używany przez wiele modeli dokumentów; dekodowany przez `readSerializable()`, więc sam jest `Serializable`. Występuje jako `dataHeader` m.in. w `ci2.PensionerData` (106), `ei2.a`/`vh2.b` (115), `yh2.b` (237), `kj2.a` (163), `wh2.a` (219). Definicji brak w przejrzanych paczkach - prawdopodobnie wspólny model odpowiedzi API w bibliotece sieciowej aplikacji (`pl.gov.coi.*`) albo paczka modelowa >199.
- `vl.c` - zaciemniona adnotacja nazwy serializowanej (patrz 105_model.md).
- `fr.t` - `kotlin.jvm.internal.Intrinsics` (biblioteka).
