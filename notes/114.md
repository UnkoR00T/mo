# 114_model.md

### Rola
Model danych (Parcelable) opisujący dane karty kolejowej (RailwayCard) zwrócone przez backend: dane posiadacza, dane pracodawcy, klasę wagonu, status, terminy ważności oraz kod QR do skanowania. Dziedziczy po `vh2.a` (klasa bazowa aplikacji, brak definicji w tej paczce). Plik: `ei2/RailwayCardData.java`.

### Endpointy
brak — klasa czysto modelowa, bez wywołań sieciowych.

### Modele danych
`ei2.RailwayCardData` (extends `vh2.a`, implements Parcelable) — serializowane nazwy pól z adnotacji `@vl.c(...)`:
- `validFrom` (`"iD"`): String - data początku ważności karty
- `expiryDate` (`"eD"`): String - data wygaśnięcia/ważności końcowej karty
- `qrCode` (`"qrC"`): String - zawartość kodu QR karty (do skanowania/obsługi)
- `id`: int (transient, brak `@vl.c`) - identyfikator lokalny/wewnętrzny, nie serializowany, `getId()`
- `cardRelation` (`"ot"`): String - relacja posiadacza do karty (np. rodzina/partner)
- `holderType` (`"ch"`): String - typ posiadacza (np. dorosły/dziecko/uczeń)
- `batch` (`"sr"`): String - numer seryjny/batch karty
- `number` (`"no"`): String - numer karty kolejowej
- `firstName` (`"n"`): String - imię posiadacza
- `secondName` (`"s"`): String - drugie imię posiadacza
- `lastName` (`"su"`): String - nazwisko posiadacza
- `pesel` (`"p"`): String - PESEL posiadacza
- `employer` (`"ti"`): String - nazwa pracodawcy (zakład pracy)
- `ouCategory` (`"oc"`): String - kategoria uprawnienia
- `trainClass` (`"kl"`): String - klasa wagonu / przedziału
- `annotation` (`"aD"`): String - adnotacja/opis karty
- `concession` (`"aDi"`): String - typ koncesji/ulgi
- `status` (`"sT"`): String - status karty
- `employerCode` (`"cC"`): String - kod pracodawcy
- `C1217a` (inner `Parcelable.Creator`): CREATOR - odtwarza obiekt z 18 `readString()` + `readInt()`

Pola odziedziczone z `vh2.a` (brak definicji w tej paczce): brak danych.

### Logika
brak obliczeń. Konstruktor przyjmuje 18 Stringów + int, kolejność argumentów identyczna z `writeToParcel`/`createFromParcel`. `equals` porównuje wszystkie 17 pól + `id` przez `t.c` (nullable-equals), `hashCode` — `*31` na `hashCode()` każdego pola. Plik: `ei2/RailwayCardData.java`.

### UI / metryki
brak — brak referencji do widoków/ekranów. Dane (liczba, imię, nazwisko, klasa wagonu, status, QR) są gotowe do prezentacji na ekranie karty kolejowej.

`vh2.a` — bazowa klasa nadrzędna (brak w `md/`, `rg -n "vh2"` trafia tylko `md/114_model.md`, `md/216_model.md`, `md/242_model.md` — definicji nie ma).
