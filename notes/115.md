# 115_model.md

### Rola
Wrapper odpowiedzi API dla karty kolejowej: kopiuje standardowy nagłówek danych (`xh2.a`, pole `"dh"`) z modelem karty (`ei2.RailwayCardData`, `"dc"`) w jedną jednostkę `Parcelable`. Drugi plik paczki (`fg/a.java`) to zaciemniona klasa bazowa wiadomości push (FirebaseMessaging / play-services), nie własna logika aplikacji. Pliki: `ei2/RailwayCardWrapped.java`, `fg/a.java`.

### Endpointy
brak — oba pliki to modele, bez wywołań sieciowych.

### Modele danych
`ei2.RailwayCardWrapped` (extends `vh2.b`, implements Parcelable) — `@vl.c(...)`:
- `dataHeader` (`"dh"`): `xh2.a` (Serializable) - wspólny nagłówek odpowiedzi (`getDataHeader()`)
- `dataContainer` (`"dc"`): `ei2.RailwayCardData` - właściwe dane karty kolejowej (`getDataContainer()`)
- `a` (inner `Parcelable.Creator`): CREATOR - `readSerializable()` dla nagłówka + `RailwayCardData.CREATOR.createFromParcel()`

`fg.a` (extends `kg.a`, Parcelable) - wiadomość FCM/push:
- `f62256a`: Intent - surowy Intent z wiadomości push (`h()`)
- `m()`: String - `google.message_id`, fallback `message_id`
- `p()`: Integer - `google.product_id` z `getIntExtra(..., 0)`, null gdy brak extra

Kontekst: identyczny wzorzec wrappera występuje dla innych dokumentów (`ci2.RailwayCardWrapped` w `md/106_model.md`, `kj2`, `wh2`, `zh2`), wszystkie z polem `dataHeader` typu `xh2.a` — wspólny nagłówek dla odpowiedzi dokumentów.

### Logika
brak logiki biznesowej. `writeToParcel`: `writeSerializable(dataHeader)` + `dataContainer.writeToParcel()`. `equals`/`hashCode` porównują oba pola (`t.c`, `*31`). `fg.a.m()` implementuje fallback klucza ID wiadomości (`google.message_id` → `message_id`), `fg.a.p()` zwraca `null` jeśli Intent nie ma `google.product_id`. Pliki: `ei2/RailwayCardWrapped.java`, `fg/a.java`.

### UI / metryki
brak — brak referencji do widoków. Wrapper dostarcza nagłówek + kartę do prezentacji (ekran karty kolejowej, analogicznie do `ci2`/`kj2`/`wh2`/`zh2`).

### Brakujące klasy
`vh2.b` (klasa bazowa `RailwayCardWrapped`), `xh2.a` (wspólny nagłówek danych, Serializable — brak definicji w `md/`; `rg -n "xh2"` daje tylko `md/106`, `115`, `163`, `219`, `243`), `vh2.a` (baza `RailwayCardData`, częściowo w `md/216_model.md`: pola `cardRelation`, `holderType`, `batch`, `number`, `firstName`, `secondName`, `lastName`, `id`), `kg.a`/`kg.c` (baza i helper Parcel zaciemnionej biblioteki).
