# 126_model.md

### Rola
Paczkca w całości zewnętrzna: `ig/l1.java` to **Google Play services Auth** (bazowa klasa rozwiązywania `PendingIntent` po zalogowaniu / `SignInClient`), `ib/c.java` to interfejs pomocniczy GMS, a `ii/*` to fragment biblioteki datowo-czasowej (Parcelable typu data/czas z walidacją zakresów dni/miesięcy). Zero logiki aplikacji mObywatel.

### Endpointy
brak

### Modele danych
- `ig.l1` -> PlayServicesAuthResolver (abstrakcyjna baza: obsługa anulowania/rezolucji PendingIntent, zapisuje stan w Bundle) [ig/l1.java]
  - pola: `f92223b` -> b: flaga `cancelled` (ustawiana w `j()`/`k()`), `f92224c` -> c: `AtomicReference` trzymający `i1` (błąd/status rozwiązania), `f92225d` -> d: `Handler` (main looper, do odroczonego `q()`), `f92226e` -> e: `gg.d` (fabryka statusów błędów)
- `ig.i1` (używana, nie w tej paczce) -> ResolutionResult (status `gg.a` + clientId) [ig/l1.java]
- `gg.a` -> PlayAuthStatus (status + `PendingIntent`, `m()` = kod, `r()` = PendingIntent, `toString()` = opis) [ig/l1.java]
- `ii.a0` -> ParcelableDate (data Y-M-D, `Comparable`): `e()` = dzień, `g()` = miesiąc, `j()` = rok [ii/a0.java]
- `ii.a5` -> ParcelableName (extends `ii.p1`, 4x String + `List` + enum + 2x `Double`) [ii/a5.java]
- `ii.a4`, `ii.a6`, `ii.a7` -> `Parcelable.Creator` (kreatory parcelowania dla `ii.b4`, `ii.b6`, `ii.g0.b`) [ii/a4.java, ii/a6.java, ii/a7.java]
- `ii.a` -> Parcelable z 4 polami typu `l0.a` (enum, domyślnie `l0.a.UNKNOWN`); `ii.a$a` -> builder (4 pola `l0.a`) [ii/a.java]
- `ib.c` -> interfejs: `a()` zwraca Parcelable, `b(Parcelable)` przyjmuje (konwerter parcelowania) [ib/c.java]

### Logika
- `ig.l1.e(requestCode, resultCode, Intent)`: requestCode 1 to wynik `PendingIntent` (resultCode -1 = sukces -> `p()`, 0 = błąd -> `s(status, clientId)`), requestCode 2 to sprawdzenie `gg.d.g(b())` (0 = sukces, 18 = `ERROR_CREDENTIAL_REQUIRED`, 18 vs 18 pomijane, by nie zapętlać dialogu); `<<ResolutionFailureErrorDetail>>` z Intencji trafia do `gg.a` (domyślnie 13) [ig/l1.java]
- `ig.l1.f(Bundle)` / `i(Bundle)`: serializacja stanu błędu do Bundle pod kluczami `resolving_error`, `failed_client_id`, `failed_status`, `failed_resolution` (PendingIntent) [ig/l1.java]
- `ig.l1.q(status, clientId)`: `androidx.camera.view.i.a` jako bramka compare-and-set na `AtomicReference`; przy zmianie stanu `k1` na main looperze [ig/l1.java]
- `ii.a0.k(rok, miesiąc, dzień)`: walidacja - miesiąc 1..12, dzień 1..31, miesiące 4/6/9/11 max 30, luty: 29 gdy `rok % 4 == 0` inaczej 28 (brak pełnych reguł gregoriańskich) [ii/a0.java]
- `ii.a0.compareTo`: porównanie po roku, potem miesiącu, potem dniu (odejmowanie) [ii/a0.java]
- `ii.a0.toString`: `String.format("%s-%s-%s", rok, %02d miesiąc, %02d dzień)` [ii/a0.java]
