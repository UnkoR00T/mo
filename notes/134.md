# 134_model.md

### Rola
Modele biblioteki **Places**: opcje opłat/udogodnień (`ii.o0`), opcje paliwowe/EV, dzień tygodnia (`ii.p`), przedziały godzin (`ii.p0`), sekcja recenzji (`ii.q`). Bez logiki aplikacji i bez endpointów.

### Endpointy
brak

### Modele danych
- `ii.o` -> Para list + 2 Stringi: `b()`/`c()` = String, `d()`/`e()` = `List<String>`; builder `ii.o$a` (`b/c(String)`, `d/e(List<String>)`), implementacja `ii.a1` [ii/o.java]
- `ii.o0` -> PaymentOptions (7 pól tekstowych + 2 listy): `b()` = `List<String>`, `c()`..`g()` = String (payment methods), `h()` = `List<String>`, `i()` = String (wymagany - prawdopodobnie currency code), `j()`/`k()` = String; fabryka `a(String currencyCode)` przez `ii.p2`, builder `ii.o0$a` (10 setterów + 2 listy) [ii/o0.java]
- `ii.p` -> enum DayOfWeek: SUNDAY..SATURDAY, Parcelable po `name()`, domyślnie SUNDAY przy braku danych; CREATOR anonimowy `ii.v6` [ii/p.java]
- `ii.p0` -> Okres godzin: `b()`/`c()` = `ii.e0` (Duration od/do, nullable); builder `ii.p0$a`, implementacja `ii.r2` [ii/p0.java]
- `ii.q` -> Recenzje podmiotu: `a()` = `List<ii.k>` (recenzje, wymagane), `b()` = Integer (wersja/limit); fabryka `c(Integer, List<k>)` przez `ii.c1` [ii/q.java]
- `ii.o3` (extends `k6`) -> implementacja dwóch list [ii/o3.java]
- `ii.o6` (extends `b3`) -> implementacja [ii/o6.java]
- `ii.p5` (extends `d2`) -> implementacja [ii/p5.java]
- `ii.q3` (extends `h7`) -> implementacja `(String, String, String, String, ii.e$b)` (5 pól: 4 nullable String + enum) [ii/q3.java]
- `ii.p3`, `ii/p4.java`, `ii/p6.java` -> `Parcelable.Creator` [ii/p3.java, ii/p4.java, ii/p6.java]

### Logika
- `ii.o$a.a()` i `ii.o0$a.a()`: `ak.n0.v` na obu listach (kompaktowanie/filtrowanie pustych) [ii/o.java, ii/o0.java]
- `ii.q.c(...)`: budowa sekcji recenzji (integer + lista), wymagane pola bez walidacji [ii/q.java]
- Parcelowanie nullable: `writeInt(1)` = null, `writeInt(0)` + `writeString`; enum przez `Enum.valueOf` lub `writeString(name())` [ii/q3.java, ii/p3.java, ii/p.java]
