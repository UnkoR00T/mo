# 156_model.md

### Rola
`kb4/a.java` to implementacja interfejsu `pl.gov.coi.common.network.l` — **mapowanie błędów HTTP na błędy domenowe** aplikacji mObywatel: parsuje body odpowiedzi błędnej do `PayloadErrorData` (różne wersje DTO) i rozpoznaje akcje `APP_UPDATE_REQUIRED` oraz `DEACTIVATE`. `kg/a.java` to abstrakcyjna klasa bazowa `Parcelable` implementująca `kg.d` (pusta, `describeContents() = 0`).

### Endpointy
brak (brak wywołań sieciowych; przetwarzanie odpowiedzi: `m00.a` -> `dx.i.Left`)

### Modele danych
- `kb4.a` -> `HttpErrorMapper` (implementacja `pl.gov.coi.common.network.l`): `f109789d: int = 8` (stała), `jsonSerializer: ay.j` (serializator JSON), `deactivateDomainErrorFactory: dx.a` (fabryka błędu dezaktywacji) (plik: `kb4/a.java`)
- `jb4.PayloadErrorData` -> `PayloadErrorData` (dane błędu z API): pola używane w kodzie: `getAction(): String` (akcja, np. `APP_UPDATE_REQUIRED`, `DEACTIVATE`), `getTitle(): String`, `getMessage(): String`; tworzona z `lb4.a` metodą `b.a(errorDto)` (plik: `kb4/a.java`)
- `lb4.a.OldPayloadErrorDtoV1` -> stary format błędu (payload) V1 (plik: `kb4/a.java`)

- `dx.b` -> `DomainError` (błąd domenowy); podklasy użyte: `dx.b.g.Http` (błąd HTTP z `getCode()`, `getMessage()`, `b()` = `PayloadErrorData`), `dx.b.AppUpdateRequired(label: mx.Label?, message: mx.Label?)` (plik: `kb4/a.java`)
- `dx.b.g.Http.a` -> `HttpStatusCode` (enum: `UNKNOWN` + dopasowanie po `getCode()`); `dx.b.g.Http.a.g()` -> zbiór wszystkich statusów (plik: `kb4/a.java`)

- `m00.a` -> `ApiResponse`: `getCode(): int`, `getMessage(): String`, `getErrorBody(): fv.e0`, `getOrg` (opakowany, odczyt `CONTENT_TYPE` typu zawartości); `m00.c.JSON` = typ zawartości JSON (plik: `kb4/a.java`)
- `mx.Label` -> etykieta lokalizowana (tworzona przez `mx.b.b(text, tag)`); tagi: `AppUpdateRequiredTitleLabelTag`, `AppUpdateRequiredMessageLabelTag` (plik: `kb4/a.java`)

- `kg.a` -> abstrakcyjna klasa bazowa `kg.d` (`Parcelable`), brak pól i własnej logiki (plik: `kg/a.java`)

### Logika
- `c(String json)`: wybór wersji DTO po zawartości JSON — jeśli obecne `errorCode` lub `error` -> `OldPayloadErrorDtoV1`; elif obecne `action` lub `message` lub `code` jest typu `String` -> `NewPayloadErrorDto`; w pozostałych przypadkach -> `OldPayloadErrorDtoV2` (plik: `kb4/a.java`)
- `b(m00.a response)`: mapuje kod HTTP na `dx.b.g.Http.a` iterując po `Http.a.g()` i szukając `getCode() == response.getCode()`; brak dopasowania -> `Http.a.UNKNOWN`. Body błędu przetwarzany tylko gdy `errorBody != null`, `errorBody.C()` (treść) != null, typ zawartości to `m00.c.JSON` i `fu.r.t0(strC)` (test na pusty/wzorzec) jest fałszywy — w przeciwnym razie treść odrzucana (ustawiana na `null`); następnie `c(strC)` -> DTO -> `b.a(dto)` -> `PayloadErrorData`. Wynik: `new i.Left<>(a(new dx.b.g.Http(null, statusCode, message, payloadErrorData, 1, null)))`. Logowanie przez `px.f.e(px.f.f163100a, "call, response:\n" + response, ...)`, maskowane parametrem `2` (brak wypisywania w trybie release) (plik: `kb4/a.java`)
- `a(dx.b domainError)`: dla błędów innych niż `dx.b.g.Http` zwraca wejście bez zmian. Dla HTTP: odczyt `PayloadErrorData.getAction()`; `APP_UPDATE_REQUIRED` -> `new dx.b.AppUpdateRequired(mx.b.b(title, "AppUpdateRequiredTitleLabelTag"), mx.b.b(message, "AppUpdateRequiredMessageLabelTag"))` (pominięte jeśli `title`/`message` == null); `DEACTIVATE` -> `deactivateDomainErrorFactory.b(true)`; inne akcje -> oryginalny błąd HTTP (plik: `kb4/a.java`)
- `d(dx.b)`: pomocniczo zwraca `PayloadErrorData` tylko z `dx.b.g.Http.b()`, dla innych podklas `null` (plik: `kb4/a.java`)

### UI / metryki
brak. Komunikaty `title`/`message` z odpowiedzi API są opisywane tagami `AppUpdateRequiredTitleLabelTag` / `AppUpdateRequiredMessageLabelTag`, co sugeruje wyświetlenie dialogu/dialogu wymuszenia aktualizacji aplikacji (sam ekran w innej paczce). Akcja `DEACTIVATE` najpewniej przekierowuje do ekranu dezaktywacji profilu.
