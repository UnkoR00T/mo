# 157_model.md

### Rola
`kg/b.java` to klasa narzędziowa do **odczytu obiektów `Parcelable` z `Parcel` z kontrolowanym rozmiarem** (styl `androidx.core.os` / parcelize): odczytuje nagłówek obiektu `"OM"`, weryfikuje rozmiary i przeskakuje do pozycji za obiektem. Kod pomocniczy biblioteki, bez logiki aplikacji.

### Endpointy
brak

### Modele danych
- `kg.b` -> `ParcelableReader` (statyczne metody pomocnicze, brak pól instancji) (plik: `kg/b.java`)
  - `A(Parcel, int): int` -> rozmiar pola: z 16 bitów zapisanych w `int` (gdy `(i15 & 0xFFFF0000) != 0xFFFF0000`, czyli `(i15 & -65536) != -65536`, to `char(i15 >> 16)`), w przeciwnym razie `parcel.readInt()` (plik: `kg/b.java`)
  - `B(Parcel, int)` -> przeskoczenie pola o rozmiar z `A` (plik: `kg/b.java`)
  - `C(Parcel): int` -> pozycja końca obiektu: nagłówek `t(parcel)` musi mieć `n(header) == 20293` (0x4F4D = `"OM"`), inaczej `BadParcelException("Expected object header. Got 0x...")`; sprawdzane `pos + size >= pos && <= parcel.dataSize()`, inaczej wyjątek `"Size read is invalid start=... end=..."` (plik: `kg/b.java`)
  - `t(Parcel)`: `readInt`; `n(int)`: `(char) i15`; `m(Parcel, int)`: `"Overread allowed size end=..."` gdy `dataPosition() != end` (plik: `kg/b.java`)
  - `D(Parcel, int, int)` / `E(Parcel, int, int, int)`: walidacja rozmiaru z komunikatami `"Expected size <oczekiwany> got <otrzymany> (0x<hex>)"` (plik: `kg/b.java`)
  - Odczyt wartości: `a` -> `Bundle`, `b` -> `byte[]`, `c` -> `byte[][]` (najpierw `readInt` jako rozmiar tablicy), `d` -> `float[]`, `e` -> `int[]`, `f` -> `ArrayList<Integer>`, `g` -> `T extends Parcelable` przez `Parcelable.Creator`, `h` -> `String`, `i` -> `String[]`, `j` -> `ArrayList<String>`, `k` -> `T[]` przez `createTypedArray`, `l` -> `ArrayList<T>` przez `createTypedArrayList`, `o` -> `boolean` (rozmiar 4, `readInt() != 0`), `p` -> `byte` (4), `q` -> `double` (8), `r` -> `float` (4), `s` -> `Float` (nullable, rozmiar 4), `u` -> `IBinder` (`readStrongBinder`), `v` -> `int` (4), `w` -> `Integer` (nullable, 4), `x(Parcel, int, List, ClassLoader)` -> `readList`, `y` -> `long` (8), `z` -> `Long` (nullable, 8) (plik: `kg/b.java`)
- `kg.b$a` -> `BadParcelException extends RuntimeException` (komunikat + `" Parcel: pos=<pos> size=<size>"`) (plik: `kg/b.java`)

### Logika
- Każdy odczyt: najpierw `A(parcel, i15)` daje rozmiar; `0` -> `null` (lub `return` dla `x`/`B`); po odczycie `setDataPosition(dataPosition + rozmiar)`; typy `Float`/`Integer`/`Long` dodatkowo sprawdzają zgodność rozmiaru w `E` (`4`/`8`), typy prymitywne w `D` (plik: `kg/b.java`)
- `f`: rozmiar listy z `readInt()`, potem każdy element jako `readInt()` (brak `readValue`-ów obiektowych) (plik: `kg/b.java`)
- `c`: tablica `byte[][]` o rozmiarze z `readInt()`, elementy przez `createByteArray()` (plik: `kg/b.java`)
- Brak logiki domenowej, interwałów, agregacji.
