# 158_model.md

### Rola
Biblioteka `androidx.core.os.SafeParcelable` (zaciemniona do pakietu `kg`): para `kg/c` (zapis) + `kg/b` z poprzedniej paczki (odczyt) implementuje bezpieczny, wersjonowany format `Parcel` z nagłówkiem `"OM"` (`0x4F4D`) i jawnymi rozmiarami pól. `kg/d` to interfejs `SafeParcelable`, `kg/e` to pomocnik odtwarzania obiektów z `byte[]` i z `Intent`. Brak logiki aplikacji.

### Modele danych
- `kg.c` -> `SafeParcelableWriter` (klasa statyczna, brak pól instancji; zapis pól do `Parcel` w formacie „rozmiar + wartość”) (plik: `kg/c.java`)
  - `a(Parcel)` -> zapis nagłówka obiektu: `writeInt(20293 | 0xFFFF0000)`, `writeInt(0)`, zwraca `dataPosition()` (plik: `kg/c.java`)
  - `b(Parcel, int)` -> zamknięcie pola: nadpisuje wartość rozmiaru zapisaną 4 bajty wcześniej jako `dataPosition() - start`, wraca do pozycji końcowej (plik: `kg/c.java`)
  - `C(Parcel, Parcelable, int)` (prywatna) -> zapis zagnieżdżonego `Parcelable` wraz z jego długością (`writeInt(1)` + `writeToParcel` + długość) (plik: `kg/c.java`)
  - `z(Parcel, int, int)` (prywatna) -> nagłówek pola stałego rozmiaru: `writeInt(id | (rozmiar << 16))` (plik: `kg/c.java`)
  - mapowanie metod na typy: `c` -> `boolean` (`1`/`0`, rozmiar 4), `e` -> `byte`, `h` -> `double` (8), `i` -> `float`, `k` -> `Float` (nullable), `l` -> `IBinder` (`writeStrongBinder`), `m` -> `int`, `n` -> `int[]`, `o` -> `List<Integer>` (rozmiar + `writeInt` per element), `p` -> `Integer` (nullable), `q` -> `List` (`writeList`), `r` -> `long` (8), `s` -> `Long` (nullable), `u` -> `String`, `v` -> `String[]`, `w` -> `List<String>` (`writeStringList`), `x` -> `T[] extends Parcelable` (długość + `C` per element, `0` dla null), `y` -> `List<T extends Parcelable>` (rozmiar + `C(...,0)` per element), `t` -> `Parcelable` (przekładane do `writeToParcel(flags)`), `d` -> `Bundle` (`writeBundle`), `f` -> `byte[]`, `g` -> `byte[][]` (długość + `writeByteArray`) (plik: `kg/c.java`)
  - Semantyka nulli: obiekty/tablice/listy/stringi -> `z(parcel, id, 0)` (rozmiar 0 = null) tylko gdy flaga `z15` (nullable) jest true; przy `false` wartość w ogóle nie jest zapisywana (plik: `kg/c.java`)
- `kg.d` -> `SafeParcelable` (interfejs `Parcelable` ze stałą `String NULL = "SAFE_PARCELABLE_NULL_STRING"`, czyli null zapisywany jako `"SAFE_PARCELABLE_NULL_STRING"`) (plik: `kg/d.java`)
- `kg.e` -> `SafeParcelableCompat` (2 metody statyczne) (plik: `kg/e.java`)
  - `a(byte[], Creator<T>)` -> `T` odtworzony: `Parcel.obtain()` + `unmarshall(bytes,0,len)` + `setDataPosition(0)` + `creator.createFromParcel()` + `recycle()` (plik: `kg/e.java`)
  - `b(Intent, String, Creator<T>)` -> `T` lub `null`: pobiera `intent.getByteArrayExtra(key)` i deleguje do `a` (plik: `kg/e.java`)

### Logika
- Format pola: obiekty złożone zapisywane jako `[rozmiar w 2 dolnych bajtach inta | 0xFFFF0000 w górnych]` + `writeInt(0)` jako rezerwa, następnie `b(...)` wpisuje faktyczny rozmiar w zarezerwowanym miejscu (plik: `kg/c.java`)
- Pola o stałym rozmiarze (`boolean/byte/short/char/int/long/float/double` oraz ich nullable odpowiedniki) zapisują rozmiar w górnych 16 bitach tego samego inta (`z`), bez rezerwy (plik: `kg/c.java`)
- Tablice/listy obiektów zapisują najpierw `int length`, potem elementy przez `C` (każdy ze swoim rozmiarem; element null jako `writeInt(0)`) (plik: `kg/c.java`)
- Brak logiki domenowej, konwersji, agregacji, interwałów czasowych.
