# 174_model.md

### Rola
`p006NUl/h.java (część 2/2)` to dalsza część `ActivityResultRegistry` z **androidx.activity**: publiczne API rejestracji launcherów (`register` z i bez `LifecycleOwner`), obsługa wyników (`onActivityResult`, `dispatchResult`), serializacja stanu do `Bundle` (`save/restore`) i wyrejestrowywanie kluczy. Kod biblioteczny androidx.activity, brak logiki aplikacji.

### Modele danych
- `p006NUl.h` (kontynuacja klasy z 173_model.md) -> `ActivityResultRegistry` (plik: `p006NUl/h.java`)
  - `keyToLifecycleContainers` -> `Map<String, p006NUl.h$c>`: klucz launchera -> kontener obserwatorów Lifecycle (plik: `p006NUl/h.java`)
  - `q(String key)` -> jeśli klucza nie ma w `keyToRc`, przydziela nowy requestCode przez `e(i(), key)` (plik: `p006NUl/h.java`)
  - `f(int requestCode, int resultCode, Intent data): boolean` -> `onActivityResult`: brak klucza w `rcToKey` -> `false`; inaczej `h(key, resultCode, data, keyToCallback.get(key))` i `true` (plik: `p006NUl/h.java`)
  - `g(int requestCode, O result): boolean` -> `dispatchResult` (wynik już sparsowany): brak klucza -> `false`; brak callbacka -> zapis do `parsedPendingResults` i `true`; `launchedKeys.remove(key)` == false -> `true` (wynik porzucony, nie było odpalenia); inaczej `callback.a(result)` (plik: `p006NUl/h.java`)
  - `k(int requestCode, b0<I,O> contract, I input, s5.c options)` -> abstrakcyjne uruchomienie kontraktu (plik: `p006NUl/h.java`)
  - `l(Bundle savedInstanceState)` -> `restoreState`: odczyt `KEY_COMPONENT_ACTIVITY_REGISTERED_RCS` (`ArrayList<Integer>`), `..._REGISTERED_KEYS` (`ArrayList<String>`), `..._LAUNCHED_KEYS` (`ArrayList<String>`), `KEY_COMPONENT_ACTIVITY_PENDING_RESULT` (`Bundle`); dla każdej pary usuwa starą rejestrację, o ile nie ma oczekującego wyniku, i odtwarza `e(rc, key)` (plik: `p006NUl/h.java`)
  - `m(Bundle outState)` -> `saveState`: zapisuje `ArrayList(keyToRc.values())` jako `..._REGISTERED_RCS`, `ArrayList(keyToRc.keySet())` jako `..._REGISTERED_KEYS`, `launchedKeys` jako `..._LAUNCHED_KEYS`, kopię `pendingResults` jako `..._PENDING_RESULT` (plik: `p006NUl/h.java`)
  - `n(key, q lifecycleOwner, b0<I,O> contract, p006NUl.d<O> callback): p006NUl.e<I>` -> `register(key, lifecycleOwner, contract, callback)`: stan Lifecycle `>= STARTED` -> `IllegalStateException("LifecycleOwner ... is attempting to register while current state is .... LifecycleOwners must call register before they are STARTED.")`; `q(key)`, tworzenie/re użycie `h$c`, obserwator delegujący do `h.p(...)`, zwrot `new d(key, contract)` (plik: `p006NUl/h.java`)
  - `o(key, b0<I,O> contract, p006NUl.d<O> callback): p006NUl.e<I>` -> `register(key, contract, callback)` bez Lifecycle: `q(key)`, zapis `keyToCallback[key] = a(callback, contract)`, natychmiastowe dostarczenie wyniku z `parsedPendingResults` lub parsowanie `pendingResults` przez `contract.c(resultCode, data)`, zwrot `new e(key, contract)` (plik: `p006NUl/h.java`)
  - `r(String key)` -> `unregister`: usuwa `keyToRc`/`rcToKey` (chyba że klucz jest w `launchedKeys`), callback, wynik oczekujący z logiem Sentry `c2.g("ActivityResultRegistry", "Dropping pending result for request " + key + ": " + ...)` oraz kontener Lifecycle (plik: `p006NUl/h.java`)

### Logika
- Trzy warstwy oczekujących wyników: `pendingResults` (Bundle, `Parcelable` z `resultCode`+`Intent`), `parsedPendingResults` (już zdeserializowane przez contract), `launchedKeys` (klucze bez odpowiedzi) (plik: `p006NUl/h.java`)
- Parowanie `rc <-> key` jest dwukierunkowe i spójne w `e()`, `q()`, `l()`, `r()`; przy restore pary z oczekującym wynikiem nie są nadpisywane (plik: `p006NUl/h.java`)
- Stany zapisu są kluczowane stałymi nazwami z `ActivityResultRegistry` (`KEY_COMPONENT_ACTIVITY_*`); brak operacji na danych domenowych, interwałach czy agregacjach (plik: `p006NUl/h.java`)
