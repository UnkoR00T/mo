# 203_model.md

### Rola
Wszystkie pliki (`th/a.java` … `th/l.java`) należą do biblioteki **play-services-auth / play-services-base** (Google Play Services). `th/a` to klient wewnętrznej usługi `ISignInService` (bind przez `com.google.android.gms.signin.service.START`, logowanie `SignInClientImpl`), pozostałe to wyłącznie obiekty `Parcelable` wyników logowania (GoogleSignInResult / ResolveSignInState) z ich `CREATOR`. Zero logiki aplikacji mObywatel.

### Endpointy
brak — brak HTTP/Retrofit. Jedyna interakcja to IPC/binder do usługi GMS `"com.google.android.gms.signin.internal.ISignInService"` (akcja `"com.google.android.gms.signin.service.START"`, `th/a.java:B()`,`th/a.java:C()`). Brak podpisywania, brak tokenów pobieranych przez tę paczkę.

### Modele danych
Wszystkie to wewnętrzne komunikaty play-services (nie encje aplikacji), plik `th/*.java`:
- `th/a` (`obf: SignInClientImpl`) — nie model, klient GMS. Pola: `L: boolean - czy "showConsentUi"`, `M: jg.e - konfiguracja GoogleSignInOptions (account, sessionId)`, `N: Bundle - parametry wywołania`, `O: Integer - sessionId`, `P: int - synthetic`. `th/a.j0()` buduje Bundle z kluczami `com.google.android.gms.signin.internal.*` (clientRequestedAccount, offlineAccessRequested=false, idTokenRequested=false, serverClientId=null, usePromptModeForAuthCode=true, forceCodeForRefreshToken=false, hostedDomain=null, realClientPackageName).
- `th/b` (`obf: SignInResolutionIntentResult/GoogleSignInResult`) — `a: int - stała wersji/kod (konstruktor domyślny 2)`, `b: int - status/kod wyniku (0 = SUCCESS, inaczej błąd → Status.f29011k)`, `c: Intent - intencja rozwiązania problemu logowania`. `b()` mapuje `status==0` → `Status.f29007f` (SUCCESS) inaczej `Status.f29011k`.
- `th/c` (`obf: CREATOR dla SignInResult`) — Parcelable.Creator, bez pól.
- `th/h` (`obf: SignInServerAuthCodeResult`) — `a: List<String> - lista kodów autoryzacji serwerowych`, `b: String - status/nonnull-token; b!=null → SUCCESS`. Zapis Parcel pole 1 = lista, 2 = string.
- `th/i` (`obf: CREATOR dla SignInServerAuthCodeResult`) — bez pól.
- `th/j` (`obf: SignInRpc/pendingSignInParcelable`) — `a: int - kod operacji (1 = signIn RPC, 2 = błąd)`, `b: jg.l0 - obiekt żądania do ISignInService (account, sessionId, hostedDomain)`.
- `th/k` (`obf: CREATOR dla SignInRpc`) — bez pól.
- `th/l` (`obf: SignInResponseParcelable / wynik signInResponse`) — `a: int - kod operacji (1 = sukces, 2 = błąd)`, `b: gg.a - obiekt Status/błąd (gg.a(8,null) = błąd RPC)`, `c: jg.n0 - odpowiedź serwisu ISignInService`. Gettery `h()` → `b`, `m()` → `c`.

### Logika
- `th/a.f()`: pobiera konto z `jg.e.b()`, buduje `jg.l0(account, sessionId, hostedDomain)`; `hostedDomain` ustawiane tylko gdy nazwa konta == `"<<default account>>"` (wartość z `cg.a.a(v()).b()`), wtedy `null`. Wyjątek `RemoteException` → log `"SignInClientImpl"` (Sentry `io.sentry.android.core.c2`) i wywołanie `k2(...)` z `gg.a(8, null)` (błąd) — `th/a.java:74-87`.
- `th/a.x()`: do Bundla dokłada `realClientPackageName`, gdy pakiet procesu różni się od `eVar.d()` — `th/a.java:114-120`.
- `th/b.b()` i `th/h.b()`: jedyne „przeliczenia” — mapowanie kodu na `Status` (0/non-null = SUCCESS, inaczej błąd).
- Brak agregacji, interwałów, filtrów poza `!= null` dla tokenu/kodu.

### UI / metryki
Brak komponentów aplikacji. Jedyna wzmianka o UI: `th/a` pole `usePromptModeForAuthCode=true` (wymuszenie trybu consent UI GMS), `th/b.c` przechowuje `Intent` do pokazania systemowego UI rozwiązania logowania. Brak kafelków/metryk.

### Brakujące klasy
- `jg/l0` — żądanie RPC do ISignInService (konto/sessionId/hostedDomain), `th/j.java` referuje.
- `jg/n0` — odpowiedź ISignInService, `th/l.java` referuje.
- `jg/e` — GoogleSignInOptions (konfiguracja logowania), `th/a.java` referuje.
- `gg/a` — opakowany `Status`/błąd GMS, `th/l.java` referuje.
- `jg/h`, `jg/c` — baza klienta GMS do bindowania usługi, `th/a.java` referuje.
- `hg/f`, `hg/l` — interfejsy callbacków GMS.
- `kg/a`, `kg/b`, `kg/c` — pomocnicze read/write Parcel (SafeParcelable), `th/*.java`.
