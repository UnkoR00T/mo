# 219_model.md

### Rola
Trzy niezależne modele: (1) `wh2/AdvocateData.java` - koperta odpowiedzi backendu dla **legitymacji adwokackiej** (kontener + wspólny nagłówek), (2) `xd4/DynamicDocument.java` - **referencja do dokumentu typu dynamic** (IID dokumentu + rodzaj), (3) `wj/g.java` - biblioteczna klasa bazowa callbacku play-core in-app review (nie aplikacji).

### Endpointy
brak (w paczce nie ma interfejsów Retrofit ani wywołań HTTP)

### Modele danych

**`wh2.c` (`wh2/AdvocateData.java`)** - envelope odpowiedzi API (wzorzec identyczny jak `ci2.PensionerData` z 106_model.md):

| pole obf | adnotacja | typ | nazwa czytelna | znaczenie |
|---|---|---|---|---|
| `a` | `@vl.c("dc")` | `AdvocateCardData` (`wh2.a`) | `dataContainer` | dane legitymacji adwokackiej (paczka 218_model.md) |
| `b` | `@vl.c("dh")` | `xh2.a` | `dataHeader` | wspólny nagłówek odpowiedzi backendu (Serializable) |

- `wh2.c$a` -> `AdvocateData.CREATOR`: `AdvocateCardData.CREATOR.createFromParcel(parcel)` + `(xh2.a) parcel.readSerializable()` (plik: `wh2/AdvocateData.java`)
- `writeToParcel`: `dataContainer.writeToParcel(dest, flags)` + `dest.writeSerializable(dataHeader)`; `describeContents() == 0`; `hashCode` = `container*31 + header` (bez null-checków) (plik: `wh2/AdvocateData.java`)
- `equals`/`toString` generowane z obu pól przez `fr.t.c` (plik: `wh2/AdvocateData.java`)

**`xd4.f` (`xd4/DynamicDocument.java`)** - implementuje interfejs `xd4.u`, `Parcelable`:

| pole obf | typ | nazwa czytelna | znaczenie |
|---|---|---|---|
| `a` | `String` | `documentIID` | wewnętrzny identyfikator (IID) dokumentu |
| `b` | `rq0.b.EnumC4479b` (`rq0.b$b`) | `documentType` | enum rodzaju dokumentu dynamic (ma metodę `getReferenceName()`, patrz 692_ui.md) |

- `xd4.f$a` -> `DynamicDocument.CREATOR`: `readString()` + `rq0.b.b.valueOf(parcel.readString())` (enum po **nazwie**, nie po indeksie) (plik: `xd4/DynamicDocument.java`)
- `writeToParcel`: `writeString(documentIID)` + `writeString(documentType.name())` (plik: `xd4/DynamicDocument.java`)
- `public static final int f218069c = 8` - stała towarzysząca obfikacji pola obiektu (brak użycia w klasie) (plik: `xd4/DynamicDocument.java`)
- Ten sam typ służy do nawigacji: `id4.i.ToDynamicDocument(dynamicDocumentType)` (380_ui.md), a typ enum trafia do bundla pod kluczem `"DYNAMIC_DOCUMENT_TYPE"` (692_ui.md, tag `TAG_DYNAMIC_DOCUMENT`)

**`wj.g` (`wj/g.java`)** - biblioteka `com.google.android.play.core.inappreview`: abstrakcyjna baza callbacku `IInAppReviewServiceCallback`; `l3(int, Parcel, Parcel, int)` obsługuje wyłącznie transakcję `2` - czyta `Bundle` przez `Bundle.CREATOR`, wywołuje `x(bundle)` (abstrakcyjne `wj.h.x`), a przy niedokończonym `Parcel` rzuca `BadParcelableException("Parcel data not fully consumed, unread size: " + dataAvail)` (plik: `wj/g.java`)

### Logika
- brak obliczeń, filtrów, agregacji i interwałów we wszystkich trzech klasach (wyłącznie `equals`/`hashCode`/`toString`/`Parcelable` boilerplate).
- Serializacja parselowa jest „ręczna" (kolejność pól w `CREATOR` musi odpowiadać `writeToParcel`), brak `Parcelize`.

### UI / metryki
brak w tej paczce. Powiązane ekrany (poza paczką): nawigacja do dokumentu dynamic przez `ToDynamicDocument` (380_ui.md), tag `TAG_DYNAMIC_DOCUMENT` (692_ui.md).
