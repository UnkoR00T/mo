# 233_model.md

### Rola
Kolejna paczka biblioteki **Google Play Services `wallet`** — nie aplikacji mObywatel. Zawiera warstwę danych `PaymentData` (odpowiedź z Google Pay odczytana z `Intent` po extrakcie `com.google.android.gms.wallet.PaymentData`), builder `PaymentDataRequest` z walidacją oraz `PaymentDataResponse`. Wszystkie pola to zaciemnione litery; znaczenia wynikają wyłącznie z komunikatów walidacyjnych i przypisań w `writeToParcel`.

### Endpointy
brak — brak wywołań sieciowych ani adresów URL. Dane płatnicze przychodzą przez `Intent` z zewnątrz (Google Pay), a response JSON to `responseJson` przekazywany jako `String`.

### Logika
- `yh.j.h(String str)` — **fast path z JSON**: tworzy builder przez `m()`, wymusza nie-null (`jg.s.m`, komunikat `paymentDataRequestJson cannot be null!`), przypisuje `f226880k = str`, zwraca `builder.a()` (plik: `yh/j.java`)
- `yh.j.m()` — **deprecated** builder bezargumentowy: `new j.a(new j(), null)`; konstruktor pusty ustawia `f226879j = true` (plik: `yh/j.java`)
- `yh.j.a.a()` — **walidacja kompletności żądania**, kolejność sprawdzeń z komunikatami GMS: (1) jeśli `f226880k == null && f226881l == null` -> loguje `Allowed payment methods must be set! You can set it through addAllowedPaymentMethod() or addAllowedPaymentMethods() in the PaymentDataRequest Builder.`; (2) `f226873c == null` -> `Card requirements must be set!`; (3) jeśli `f226877g != null` (są info transakcji) to `f226878h == null` -> `Transaction info must be set if paymentMethodTokenizationParameters is set!`. W każdym przypadku zwracany jest ten sam obiekt `j` (plik: `yh/j.java`)
- `yh.i.h(Intent)` — deserializacja `PaymentData` z `Intent` po stałym kluczu extra `com.google.android.gms.wallet.PaymentData` (plik: `yh/i.java`)
- `yh.j`, `yh.i`, `yh.k` — poza `writeToParcel` brak logiki; brak obliczeń, filtrów, agregacji i interwałów.
