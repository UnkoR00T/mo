# 237_model.md

### Rola
Paczka zawiera trzy warstwy: (a) model domenowy opakowujący dane karty posła (`yh2/DeputyCardWrapped`) jako domyślna klasa Kotlinowa implementująca `Parcelable` + serializację kotlinx; (b) dwie klasy wewnętrzne `kotlinx-serialization-core` generujące komunikaty błędów o braku serializatora (`yu/c.java`, `yu/c1.java`); (c) `Parcelable.Creator` dla klasy domenowej z innego pakietu (`zg/c1.java`). Część (a) i (c) to kod aplikacji, część (b) to biblioteka.

### Endpointy
brak — żadna klasa nie zawiera URL, metody HTTP, ani obsługi tokenów.

### Modele danych

**`yh2/DeputyCardWrapped`** (oryg. `yh2.b`, plik `yh2/DeputyCardWrapped.java`) — koperta odpowiedzi API dla karty posła; struktura typowa dla serwisu dokumentów mObywatela: `dataHeader` + `dataContainer`.
- `dataHeader`: `xh2.a` - nagłówek metadanych dokumentu (klasa `Serializable`, brak definicji w `md/`); serializowane pole `"dh"`.
- `dataContainer`: `DeputyCardData` - właściwe dane karty posła (definicja w `md/236_model.md`); serializowane pole `"dc"`.
- Adnotacje serializacyjne to `vl.c(...)` = `kotlinx.serialization.SerialName` (skrócona nazwa pola: `dh`/`dc`).
- Konstruktor: `DeputyCardWrapped(xh2.a, DeputyCardData)`; gettery `getDataHeader()` / `getDataContainer()`.
- `writeToParcel`: `dataHeader` przez `Parcel.writeSerializable`, `dataContainer` przez własne `writeToParcel` — dwie różne ścieżki serializacji w jednym obiekcie.
- `hashCode`/`equals`/`toString` wygenerowane (data class): `hashCode = dataHeader.hashCode()*31 + dataContainer.hashCode()`.

**`yh2/DeputyCardData`** (odwołanie, pełne pola w `md/236_model.md`) — `firstName` (`"n"`), `secondName` (`"s"`), `lastName` (`"su"`), `number` (`"no"`), `numberOfSeymCadency` (`"pTNo"`), `releaseDate` (`"rD"`); wszystkie `String`.

**`zh2/FamilyCardData`** (brak w tej paczce, `md/242_model.md`) — ta sama rodzina kopert: `dataContainer` + `dataHeader`.

**Rejestracja w mapperze** (`md/444_ui.md:149` `DeputyCardScope S(DeputyCardDataDto)`): nagłówek DTO jest mapowany przez `l1(...)` na `j24.IdentityDataHeader`, a kontener przez `R(...)` na `DeputyCardContainerData(firstName, secondName, lastName, number, numberOfParliamentCadence, releaseDate)` (`md/444_ui.md:141`). Nazwy pól Kotlinowe potwierdzają czytelność semantyczną: `numberOfParliamentCadence` = kadencja Sejmu, `releaseDate` = data wydania.

**`zg/c1.java`** — `Parcelable.Creator` (surowa, nie generowana) dla klasy `zg.f0`; odtwarza pola z `Parcel` przez `kg.b` wg indeksów tagów: `1` -> `int` (`iV`), `3`/`4`/`6` -> trzy `String` (`strH`, `strH2`, `strH3`), `7` -> `zg.f0` (`f0Var`, zagnieżdżony obiekt), `8` -> `ArrayList<gg.c>` (`arrayListL`); nieznany tag -> `kg.b.B` (pominięcie). Brak klasy `zg.f0` w `md/` (jest tylko `zg/f0.java` w `md/238_model.md` jako inna klasa o tej samej nazwie pakietowej).

### Logika
- Brak logiki biznesowej: brak obliczeń, przeliczeń, filtrów, agregacji i interwałów.
- Jedyne zachowania to standardowe implementacje `equals`/`hashCode` (data class) oraz round-trip Parcelable (`md/237_model.md` `DeputyCardWrapped.java:39,89`).
- `yu/c.java`: `a(String, mr.c)` buduje komunikat „Class discriminator was missing…"/„Serializer for subclass … is not found" i rzuca `uu.n`; `b(...)` rzuca `oq.g`. `yu/c1.java`: `a(SerialDescriptor)` zwraca zbiór nazw elementów (lub deleguje do `k.a()` dla własnego deskryptora), `b(List)` normalizuje listę deskryptorów do pustej tablicy, `c`/`d`/`e` generują/throwują „Serializer for class '…' is not found". Wszystko to `kotlinx-serialization-core`, nie logika aplikacji.

### UI / metryki
Brak. Klasa nie zawiera widoków, tekstów, kolorów ani zasobów; `DeputyCardScope`/`DeputyCardContainerData` (konsument w `md/444_ui.md`) to warstwa prezentacji używana przez `MultiDocumentView`/`VerificationSelector` (`md/444_ui.md:46-47`).
